# Stencil Asset Manifest

This document governs everything under `assets/stencil/`. Read it before
adding, moving, or referencing any file in this tree.

This is an **asset library setup document only**. It does not select assets
for landing-page sections, does not make visual design decisions, and does
not import or generate any AI assets. Those are separate, later decisions.

---

## 1. Production assets

Production assets are the only assets that may eventually appear on the
public Stencil landing page. To qualify, an asset must be one of:

- created by us
- photographed/scanned by us
- generated by us
- otherwise explicitly licensed for our use

If an asset does not meet one of these four conditions, it is not a
production asset — it belongs in `references/external/` instead, and stays
there.

## 2. External references

Anything downloaded from websites, Wikimedia, Unsplash, Pinterest, design
archives, or similar sources belongs **only** in:

```
assets/stencil/references/external/
```

External references are visual research. They must **never** be
automatically imported into the production landing page. Moving something
out of `references/external/` and into a production category is a
deliberate, separate act — check licensing, then follow the provenance
template below and get explicit sign-off before treating it as production.

## 3. Material vocabulary

```
assets/stencil/
├── material/
│   ├── photocopy/           halftone, toner irregularity, reproduction noise, photocopy degradation
│   ├── riso/                registration offset, ink overlap, imperfect reproduction, colour separation
│   ├── tracing/              translucent layers, supersession, visible previous states
│   ├── paper/                real paper grain, edges, folds, physical surface
│   └── scan-interference/   moiré, scanning artefacts, reproduction interference
│
├── human-trace/
│   ├── handwriting/          handwritten notes, annotations, authored text
│   ├── pencil/                sketches, underlines, provisional notation
│   ├── correction/           strikethroughs, crossed-out text, white-out, redlines
│   └── marks/                stamps, checkmarks, circling, arrows, other authored annotation
│
├── physical/
│   ├── tape/                  tape, adhesive residue, attachment marks
│   └── edges/                torn paper, cut lines, deckled edges, card boundaries
│
└── references/
    └── external/              downloaded web references — research only, never production
```

Each leaf folder has its own `README.md` documenting status and what
belongs there.

## 4. Production asset principle

Material should not be added merely because it looks "experimental."

Every production asset must answer: **why does this material exist? what
event does it imply?**

| Material | Event it implies |
|---|---|
| photocopy | reproduction |
| riso | reproduction under mechanical imprecision |
| tracing | supersession — a new version laid over an old one |
| paper edge | a physical boundary |
| scan interference | imperfect transmission |
| handwriting | human judgment |
| pencil | provisional human judgment |
| correction / strike | rejection while retaining evidence |
| marks | human judgment applied to an existing object |
| tape | attachment evidence |

If a candidate asset can't answer this question, it doesn't belong in the
production tree, no matter how visually interesting it is.

## 5. Do not fabricate assets

Do not create fake placeholder JPG/PNG textures to fill out the tree. Where
a category has no real asset yet, the folder's `README.md` is the only file
in it, marked `AWAITING PRODUCTION`. Fabricated placeholders would be
indistinguishable from real production assets later — that ambiguity is not
allowed.

## 6. Asset status system

Every asset (once real assets exist) is classified as exactly one of:

| Status | Meaning |
|---|---|
| `REFERENCE` | Visual research only, in `references/external/`. Never production. |
| `TEST` | Being trialed — captured/created but not yet evaluated for production use. |
| `PRODUCTION` | Meets the production-asset bar (§1) and is cleared to use. |
| `APPROVED` | Production asset that has been explicitly signed off for a specific use. |
| `RETIRED` | No longer in use; kept for record, not for reuse. |

Status is recorded per-asset in the provenance log (§7), not inferred from
folder location alone.

## 7. Provenance template

Every production asset must have a provenance record. Copy this block into
a per-asset note (or a running log in the relevant category folder) when a
real asset is added:

```
Asset name:
Category:
Created by:
Source:
Date:
Generation method:
Original / derived:
Licence:
Usage rights:
Used in:
Status:
```

No asset moves from `TEST` to `PRODUCTION` or `APPROVED` without this
record filled in.

## 8. Boundaries of this setup

This manifest and directory structure do **not**:

- select or place any asset into a landing-page section
- modify the landing page itself
- generate AI-produced assets
- make visual design decisions

Those happen later, in separate, explicit steps.
